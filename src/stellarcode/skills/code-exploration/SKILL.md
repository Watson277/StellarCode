# code-exploration Skill

## 目标

用最少且可复核的工作区证据完成任务。先定位，再读取；修改后验证。不要因为检索结果看起来相关就假定已经理解了真实实现。

## 选择证据入口

| 已知信息 | 首选入口 | 后续动作 |
|---|---|---|
| 已知准确文件路径 | `read_file` | 只读取解决问题所需的内容 |
| 只知道文件名、扩展名或目录模式 | `glob_files` | 从候选文件中选择相关路径 |
| 已知类名、函数名、配置键、错误文本或其他准确字符串 | `grep_code` | 按命中行读取必要上下文 |
| 只知道模糊职责、跨模块行为或自然语言概念 | `search_code` | 检查返回路径与行号，再读取真实源码 |
| 需要了解一个小目录的直接内容 | `list_dir` | 不把目录列表当作源码证据 |

`search_code` 必须遵守 system prompt 的 Runtime capability state，不在 Skill 中重新定义该模式。没有索引、索引过期或结果不相关时，回到文件模式、准确文本和源码读取，不要把零结果解释成代码不存在。

## 调查流程

1. 从用户目标提取最小定位线索，不做全盘递归扫描。
2. 可以并行执行互不依赖的候选文件或准确文本搜索；依赖上一步路径的读取必须随后执行。
3. 对结论依赖的实现读取真实源码。语义片段、文件名和目录列表只能用于定位。
4. 区分观察到的事实与推断；信息不足时继续缩小范围，而不是猜测。

## 修改流程

1. 修改已有文本前读取目标区域，并保留用户现有改动和项目风格。
2. 对已有文件的局部修改使用 `apply_patch`；创建新文件或明确需要完整替换时使用 `write_file`。
3. 只有用户要求或任务确实需要时才删除文件，不借助命令绕过文件修改审批。
4. 修改后重新检查关键内容，并运行与风险相称的测试、静态检查、构建或最小复现。
5. 最终说明实际修改、验证证据和仍未验证的限制；没有工具证据时不要声称操作成功。

## 并发与共享状态

- 只并行读取互不依赖的文件或运行互不影响的检查。
- 不让并发任务同时修改同一文件或共享生成物。
- 前一步会决定路径、补丁或命令时，保持顺序执行。

## 停止条件

达到用户要求且验证完成后停止。若被策略、缺失依赖、不可用索引或可复现错误阻塞，报告精确证据和继续所需的最小动作。
